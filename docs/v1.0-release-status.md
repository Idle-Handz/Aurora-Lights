# Aurora Reflections 1.0 release status

Updated October 28, 2026. RC5 has passed Windows x64 and Android ARM64 package
acceptance. Stable 1.0 preparation is waiting for SignPath approval, integration,
and validation of the final signed Windows and production-signed Android packages.

## Release and platform scope

The public [1.0.0-rc.5 release](https://github.com/Idle-Handz/Aurora-Lights/releases/tag/v1.0.0-rc.5)
is an unsigned Windows x64 prerelease, published October 27 without marking it
latest. It contains the installer, portable package, updater
payload/feed, checksums, and matching corresponding source. Android was validated
locally and on the connected phone; its APK was not uploaded to that release.

RC5 is frozen at commit `31061868c3f6d21342b3a9ca2cf43f36a996f4d2` on
`feature_public-v1.0-build-preparation`. Documentation changes made afterward
will be included in the next freeze; they do not change the published RC5 files.

| Target | Release commitment |
| --- | --- |
| Windows x64 | Stable 1.0 target; RC5 installation, character/PDF, close/relaunch, and public updater acceptance passed. |
| Android ARM64 | Stable 1.0 target; RC5 signed in-place upgrade and physical-phone acceptance passed. |
| Windows ARM64 | Experimental. |
| macOS through Mac Catalyst | Experimental. |
| Web | Deferred; no public hosted service is offered. |

## Completed acceptance

- Hosted Tests, Windows, Android, and Legacy WPF workflows passed on the exact
  frozen RC5 commit.
- Windows clean installation, RC4 installer upgrade, portable launch, character
  loading, four combinations of PDF form/formatting options, Preview, and
  Cancel/Save close-and-relaunch behavior passed. Missing-WebView2 bootstrap
  acceptance is carried forward from RC3 because that executable bootstrap
  code section is unchanged; the missing-runtime case was not repeated for RC5.
- The published RC4-to-RC5 Windows updater passed both immediate restart and
  deferred installation after Cancel/Save. Saved edits and other synthetic
  character/session files were preserved. A WebView2 teardown diagnostic was
  recorded without an observed crash, update failure, or data loss.
- Android's existing production signing identity and application ID were retained.
  All 72 isolated ARM64 PDF checks passed, followed by installed Save PDF, Share
  PDF, and Open PDF checks. All 2,502 original external files remained byte-identical;
  the account connection was retained and synthetic test data was removed.
- The reviewed SRD-only baseline, third-party notices, PDF-library source, and
  LGPL rebuild/relink materials are included. All 2,516 canonical source files
  matched between the public automatic GitHub source archive and the corresponding
  source bundle.
- Public Google Drive sign-in and consent were verified by the maintainer and
  external testers, confirmed October 28. This closes the public-account access
  question; public users do not need development test-user enrollment.

The package records are under `artifacts/v1-rc5-2026-10-24/`, including
`final-validation.json`, `final-artifact-manifest.json`, the Android installed
acceptance, Windows visual acceptance, and `publication/acceptance-report.txt`.
These ignored local artifacts are evidence records, not public download links.
The [public release](https://github.com/Idle-Handz/Aurora-Lights/releases/tag/v1.0.0-rc.5)
provides the distributed packages, source, and checksums.

## Remaining stable release steps

1. Complete the [SignPath application and signing integration](windows-code-signing.md).
   The owner has submitted the application for the free open-source route. RC5 remains unsigned;
   stable package preparation is held until the signing route is approved.
2. Freeze the final source, including the current documentation and approved
   signing workflow. Run hosted CI on that exact commit and build the final
   Windows x64 and Android ARM64 packages. Use the existing Android signing key
   and application ID, with a version code higher than RC5's `215061784`.
3. Validate the signed downloads: signature coverage, clean Windows installation,
   upgrade/update from an existing installed candidate, character loading, PDF
   output, and close/relaunch. Confirm the Android in-place upgrade preserves data
   and repeat focused installed character/PDF checks. Reopen broader acceptance
   only if the final changes affect those paths or a regression appears.
4. Generate corresponding source and notices from that same final revision,
   calculate checksums after signing/packaging, and publish stable `1.0.0` with
   the approved platform labels. Verify anonymous downloads and stable updater
   discovery/delivery before calling the release complete.
